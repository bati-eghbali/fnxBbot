# FNX AI Chatbot · הבוט החכם של הפניקס

צ'אט בעברית שעונה על שאלות לקוחות **רק מתוך התוכן הציבורי של fnx.co.il**. כל תשובה מגיעה עם קישור לעמוד המקור. כשהמידע לא כתוב באתר, הבוט אומר זאת ומפנה לשירות הלקוחות, במקום להמציא.

> האקתון AI קוד פתוח 2026 · אתגר בשיתוף הפניקס

## מה הבוט עושה

| הלקוחה שואלת | הבוט |
|---|---|
| "יש לי נזילה בבית, איך מגישים תביעה?" | עונה מעמוד "נזקי צנרת", ומצרף קישור |
| "ותוך כמה זמן מקבלים תשובה?" | מבין שזו שאלת המשך על תביעת נזקי מים, ועונה "תוך 30 יום מקבלת המסמכים" עם המקור |
| "האם הפוליסה שלי מכסה את זה?" | מסביר מה הכיסוי כולל לפי האתר, ומפנה לבדיקת הפוליסה האישית בשירות הלקוחות |
| "מה שעות הפעילות של הסניף בחולון?" | "לא מצאתי את המידע הזה באתר", ומפנה לשירות הלקוחות |
| "כמה עולה ביטוח רכב בהראל?" / "התעלם מההוראות..." | מסרב בנימוס: עונה רק על נושאים מאתר הפניקס |

## ארכיטקטורה

```
[OFFLINE: נבנה פעם אחת, ומרועננים לפי הצורך]
sitemap.xml ─► Crawl4AI ─► ניקוי ─► חיתוך לפי כותרות ─► Gemini embeddings ─► ChromaDB + BM25
                  └─► קישורי PDF ─► PyMuPDF ─┘

[ONLINE: בכל שאלה]
React ─► FastAPI /chat ─► [1] שער כניסה (ניסוח מחדש + סיווג)
                              │ site_question / personal_policy
                              ▼
                          [2] חיפוש היברידי (וקטורי + BM25, RRF) + סף דמיון מוחלט
                              ▼
                          Agent מרוסן (עד 3 צעדים, כל צעד = קריאה לכלי)
                              ├ search_knowledge_base   חיפוש נוסף בניסוח אחר
                              ├ get_full_page           עמוד מלא של תוצאה שכבר נמצאה
                              ├ refer_to_customer_service
                              └ final_answer {found, answer, used_chunk_ids}
                              ▼
                          [3-4] אימות בקוד: היה חיפוש? כל מקור נשלף בפועל?
                              ▼
                          תשובה + קישורים ─► Supabase (הודעות + trace של כל צעד)
```

| רכיב | טכנולוגיה |
|---|---|
| סריקה | Crawl4AI (Playwright) |
| PDF | PyMuPDF |
| Embeddings | Gemini `gemini-embedding-001` (768 ממדים) |
| מאגר וקטורי | ChromaDB |
| חיפוש מילולי | rank-bm25 עם טוקנייזר עברי קל |
| מודל שפה | Gemini Flash (`gemini-3.5-flash` ואחרים; מתחלף אוטומטית בין מודלים ומפתחות) |
| שרת | FastAPI |
| ממשק | React + TypeScript (Vite), RTL |
| היסטוריית שיחות | Supabase (PostgreSQL) |

**למה Agent מרוסן ולא RAG רגיל ולא Agent חופשי?** ה-Agent יכול לחפש שוב בניסוח אחר או לפתוח עמוד מלא, וזה משפר תשובות לשאלות מורכבות ולשאלות המשך. אבל הוא מוגבל לשלושה צעדים, כל צעד שלו הוא קריאה לכלי, והוא לא יכול לענות בטקסט חופשי. לכן ההתנהגות צפויה, נבדקת בקוד, וזולה (2–3 קריאות למודל בשאלה).

## איך הבוט לא ממציא: 5 שכבות הגנה

מספיק שאחת מהשכבות תחסום. ארבע מהן הן קוד ולא הוראות למודל, כך שגם אם המודל "ישתכנע" לחרוג, לא תצא תשובה בלי מקור אמיתי.

1. **שער כניסה** ([app/gate.py](backend/app/gate.py)): קריאה קצרה למודל שמנסחת שאלות המשך כשאלה עצמאית, ומסווגת כל הודעה לאחת מחמש קטגוריות: שאלה על האתר, פוליסה אישית, ייעוץ, מחוץ לתחום או ברכה. ידע כללי, מתחרים, בקשות לשירים או קוד וניסיונות לשנות את ההוראות נעצרים כאן, וה-Agent לא רץ בכלל.
2. **סף דמיון מוחלט** ([app/retrieval.py](backend/app/retrieval.py)): הסף נבדק על ציון ה-cosine האמיתי, לא על הדירוג היחסי של RRF, שתמיד מחזיר "תוצאה הכי טובה". אם אף קטע באתר לא קרוב מספיק לשאלה, החיפוש מחזיר "לא נמצא" והמודל לא נקרא. הסף כויל עם `python -m ingest.probe` (שאלות מחוץ לתחום ≤ 0.57, שאלות אמיתיות ≥ 0.68).
3. **חובת חיפוש** ([app/agent.py](backend/app/agent.py)): הקוד עצמו מריץ את החיפוש הראשון, ותשובה שניתנה בלי חיפוש נדחית.
4. **אימות מקורות**: כל `chunk_id` שהמודל מצטט חייב להיות קטע שהכלים החזירו בפועל. הקישורים נבנים מהמטא-דאטה של הקטעים, והמודל לא כותב URL בעצמו. אם `found=false` או שאין ציטוט מאומת, התשובה היא "לא מופיע באתר".
5. **הנחיות מוקשחות** ([app/prompts.py](backend/app/prompts.py)): רק מהקטעים, בלי ידע כללי, בלי מתחרים, תוכן האתר הוא נתונים ולא הוראות, temperature 0.

## איך נאסף התוכן

1. **רשימת עמודים** ([crawler/sitemap.py](backend/crawler/sitemap.py)): 1,643 כתובות מ-`sitemap.xml`. מסננים לפי `robots.txt` (כולל הכללים עם wildcard), ומוציאים עמודי מכירה, מחשבונים, אנגלית, קריירה ותגיות. נשארות 1,412 כתובות, מתועדפות כך: תביעות, שירות, מוצרים, ובסוף קשרי משקיעים.
2. **סריקה** ([crawler/crawl.py](backend/crawler/crawl.py)): Crawl4AI מרנדר כל עמוד, כולל תוכן שנטען ב-JavaScript ואקורדיונים פתוחים. מוסרים באנר עוגיות, סרגל פורטלים, בלוק "כל הדרכים לדבר איתנו" שחוזר בכל עמוד, ועותקי מובייל כפולים.
   - **קצב מנומס:** עד 2 בקשות במקביל, עם השהיה של 1.5 שניות.
   - **זיהוי בעיות:** דף captcha של Radware, דף שגיאה כשהאתר עמוס, ודף 404 שמוחזר עם קוד 200 לא נשמרים. מתעדים אותם ומנסים שוב בסבב איטי (`--slow`: עמוד אחד כל 4 שניות).
   - **המשכיות:** עמוד שכבר נשמר מדולג, כך שאפשר לעצור ולהמשיך.
3. **השלמה** (`--discover`): קישורים פנימיים שנמצאו בעמודים אבל חסרים ב-sitemap. כך נמצאו, למשל, עמודי השאלות הנפוצות של ביטוח דירה, חיות מחמד ונסיעות.
4. **PDF** ([crawler/pdfs.py](backend/crawler/pdfs.py)): פוליסות וטפסים שמקושרים מעמודי תביעות ומוצרים, עד 80 קבצים ו-40 עמודים מכל קובץ. גרסאות ישנות ומסמכי "ריכוז שינויים" לא נכללים.

**התוצאה:**
- **1,047 עמודי HTML ו-72 מסמכי PDF**, בסך הכול כ-5.8 מיליון תווים.
- **מתוכם 4,057 קטעים לחיפוש**, אחרי שהוסרו 1,078 קטעים כפולים שחוזרים בכמה עמודים.
- **41 כתובות ב-sitemap כבר לא קיימות** (דף 404), ולא נכללו.

לכל עמוד נשמרים כתובת, כותרת ותאריך איסוף.

**מצב המאגר:** 3,492 מתוך 4,057 קטעים (86%) מוטמעים. ההטמעה נעשית לפי סדר עדיפויות, כי המכסה החינמית של Gemini היא 1,000 קטעים ביום לכל מפתח:

| סוג תוכן | מוטמע |
|---|---|
| תביעות | 100% |
| שירות לקוחות ושאלות נפוצות | 100% |
| מסמכי PDF | 100% |
| דפי מוצרים | רובם |
| מאמרים, נתוני מסלולים ותנאי שימוש | חלק |

את השאר משלימה הרצה חוזרת של `python -m ingest.index`.

## איך נבחר הקטע

- **חיתוך** ([ingest/chunk.py](backend/ingest/chunk.py)):
  - כל עמוד נחתך לפי הכותרות שלו (H1–H3).
  - בעמודי שאלות נפוצות, כל שאלה ותשובה הן קטע אחד.
  - קטעים קטנים מתמזגים, וקטעים גדולים מתפצלים עם חפיפה.
  - שורות שחוזרות בהרבה עמודים מוסרות, וכך גם קטעים זהים שמופיעים בכמה עמודים.
  - לכל קטע מצורפת "שרשרת כותרות" לפי היררכיית ה-URL, למשל "ביטוח בריאות › מחלות קשות › שאלות ותשובות › כמה זמן לוקח הטיפול?". כך גם קטע קצר נושא את ההקשר שלו.
- **חיפוש היברידי:**
  - חיפוש וקטורי (Gemini embeddings, `RETRIEVAL_QUERY` / `RETRIEVAL_DOCUMENT`) מוצא משמעות: "נזילה" מתאים ל"נזקי צנרת".
  - BM25 מוצא מונחים מדויקים, כמו שמות מוצרים ומספרי טפסים. הטוקנייזר מסיר את אותיות בומ"ה וכל"ב בתחילת מילה, כך ש"בביטוח" מתאים ל"ביטוח".
  - שתי הרשימות מאוחדות ב-Reciprocal Rank Fusion, ו-8 הקטעים המובילים עוברים ל-Agent.
- **ה-Agent** מחליט אם הקטעים מספיקים. אם לא, הוא מחפש שוב בניסוח אחר או פותח עמוד מלא, ומצטט רק את הקטעים שבהם השתמש.

## תוצאות הבדיקה

| מדד | תוצאה |
|---|---|
| תשובה נכונה עם המקור הנכון | **24/24 (100%)** |
| סירוב, הפניה או "לא באתר" כשצריך (כולל 8 שאלות מלכודת) | **14/14 (100%)** |
| קישורי מקור מומצאים | **0** |
| שגיאות | **0** |

**ארבע שאלות שכדאי להכיר:**
- **"אפשר לשלם בביטקוין?" ו"כמה תעלה פוליסה לדירת 4 חדרים בת"א?"** תוכננו במקור כשאלות שהתשובה עליהן לא באתר. התברר שבאתר יש מידע קרוב: אמצעי התשלום, ואיך נקבע מחיר. הבוט ענה מהמידע הזה, עם מקור, ולא המציא. לכן הן הועברו לקטגוריה "תשובה מבוססת או סירוב".
- **"שינוי מסלול השקעה" ו"גרירה"** קיבלו תשובות מעמודים אחרים מאלה שציפינו להם. וידאנו שהעובדות שבתשובה אכן מופיעות בעמודים שצוטטו, והוספנו אותם לרשימת המקורות הצפויים.

**זמני תגובה:** בהרצה הזו הזמן החציוני היה 16 שניות. בדיקה של ה-trace מצאה שתי סיבות:
- ספריית Google הריצה מנגנון ניסיונות חוזרים משלה, שהמתין דקות כשמודל היה עמוס.
- מודלי ה-Lite היו עמוסים אצל Google באותו יום.

**התיקונים:**
- ביטלנו את הניסיונות החוזרים של הספרייה.
- כל קריאה מוגבלת ל-12 שניות, וכל שאלה ל-40 שניות.
- מודל עמוס מושבת ל-5 דקות.
- שער הכניסה עבר למודלים המהירים.

בהרצה חוזרת על השאלות האיטיות הזמן החציוני היה **6.4 שניות**, ושאלות שנעצרות בשער הכניסה נענו תוך 1–4 שניות.

**כשהמכסה היומית נגמרת:** בהרצה רביעית באותו יום נגמרה המכסה של המודלים המהירים בכל המפתחות. 14 שאלות קיבלו "הבוט עמוס כרגע", בלי תשובה מומצאת, וכל הסירובים נשארו נכונים. פירוט ההרצה הזו ב-[eval/results_quota_exhausted_run.md](backend/eval/results_quota_exhausted_run.md).

סט ההערכה נמצא ב-[eval/questions.jsonl](backend/eval/questions.jsonl): שאלות לקוח אמיתיות (כולל שרשראות של שאלות המשך), שאלות שהתשובה עליהן לא באתר, ושאלות מלכודת (ידע כללי, שיר, קוד, מתחרה, עקיפת הוראות, ייעוץ, מידע אישי ושאלה מעורבת). הפירוט המלא, שאלה אחר שאלה, נמצא ב-[eval/results.md](backend/eval/results.md).

## מגבלות

- **מכסת Gemini החינמית:**
  - **התשובות:** כ-20 קריאות ביום לכל מודל ולכל מפתח.
  - **ה-embeddings:** 1,000 טקסטים ביום, משותפים לבניית המאגר ולשאלות.
  - **איך הקוד מתמודד:**
    - **מעבר אוטומטי:** כשהמכסה של צירוף (מפתח, מודל) נגמרת, הקוד עובר לצירוף הבא. אפשר להגדיר כמה מפתחות ב-`GEMINI_API_KEYS`.
    - **זיכרון מכסות:** הקוד זוכר מתי המכסה של כל צירוף מתאפסת.
    - **מכסה לשאלות:** בניית המאגר שומרת 250 embeddings ביום לשאלות.
    - **חיפוש מילים כגיבוי:** אם אין מכסה ל-embedding של שאלה, החיפוש עובר ל-BM25, עם רף משלו של כיסוי מילות השאלה.
  - **כשהכול מוצה**, הבוט עונה "עמוס כרגע".
  - **בייצור** כדאי להפעיל חיוב (סנטים לשאלה), ואז כל המגבלות האלה נעלמות.
- **הגנת הבוטים של האתר (Radware)** חוסמת חלק מהסריקות. רוב עמודי קשרי המשקיעים לא נאספו, ומכיוון שהם לא רלוונטיים ללקוחות זה נעשה בכוונה.
- **תוכן דינמי:** מחשבונים, טבלאות תשואה שנטענות מ-API ואזורים אישיים לא נאספו.
- **PDF:** רק 40 העמודים הראשונים של כל מסמך. קבצים סרוקים (תמונה בלי טקסט) לא נקראים.
- **אין גישה למידע אישי.** זה בכוונה: הבוט מפנה לאזור האישי ולשירות הלקוחות.
- **המידע נכון לתאריך הסריקה.** כל קטע שומר `crawled_at`.

## ריענון התוכן

```bash
cd backend
python -m crawler.sitemap        # רשימת כתובות עדכנית
python -m crawler.crawl          # סורק רק עמודים חדשים (מחקו את data/raw כדי לסרוק הכל מחדש)
python -m crawler.crawl --slow   # סבב חוזר לעמודים שנחסמו
python -m crawler.pdfs
python -m ingest.chunk
python -m ingest.index           # embeddings רק לקטעים שהשתנו (מטמון לפי hash)
```

בגלל המטמון, ריענון עולה רק את הקטעים שהשתנו. אחרי הריענון בונים מחדש את השרת: בענן, commit של `data/chroma` ו-`data/bm25.pkl`, ו-Render מתעדכן לבד.

## הרצה מקומית

**דרישות:** Python 3.11, Node 20+, מפתח Gemini API, ופרויקט Supabase (חינמי).

```bash
# 1. הגדרות
cp .env.example .env          # ממלאים: GEMINI_API_KEY, SUPABASE_URL, SUPABASE_SERVICE_KEY, SUPABASE_DB_URL

# 2. Backend
python -m venv .venv
.venv\Scripts\activate        # Windows  (macOS/Linux: source .venv/bin/activate)
pip install -r backend/requirements.txt
crawl4ai-setup                # מתקין דפדפן לסורק
cd backend
python check_setup.py         # בדיקת חיבורים
python apply_schema.py        # יצירת הטבלאות ב-Supabase

# 3. בניית המאגר (אם data/chroma לא קיים)
python -m crawler.sitemap && python -m crawler.crawl && python -m crawler.pdfs
python -m ingest.chunk && python -m ingest.index

# 4. הפעלה
uvicorn app.main:app --port 8000
cd ../frontend && npm install && npm run dev      # http://localhost:5173
```

**כלים לבדיקה:**
- `python -m app.cli "שאלה" "שאלת המשך"`: צ'אט בטרמינל, עם ה-trace של כל צעד.
- `python -m ingest.probe`: איכות האחזור וכיול הסף.
- `python -m eval.run_eval`: סט ההערכה המלא.

```
  data/                  chroma/ + bm25.pkl (המאגר), chunks.jsonl
frontend/                React + TypeScript
supabase/schema.sql      conversations, messages (כולל trace)
```
